## Original animation

The real Bloub sprite sheet `sileo-standalone-demo/public/bloub/bloub-04-working.png` is 9216 × 64 pixels: 144 original 64 × 64 frames. The original art **already contains circle → shrink into dots → morph to triangle** (frames 0...69). v4 ships **24 source frames sampled at indices 0, 3, 6, ... 69**, without redrawing or replacing the Bloub artwork. The intended run time is 24 frames / 12 FPS = **2 seconds**.

The asset build includes `Shared/BloubAssets.xcassets/bloub-morph-00.imageset` through `bloub-morph-23.imageset`, all exported from that original sprite sheet.

## Two real-iPhone playback experiments

1. **Dynamic Island — best-effort experiment, not guaranteed video.** In Bloub tap **Start**, then **24-FRAME MORPH / 2s · Go Home in 10s**, and swipe Home immediately. The app requests a short background-execution window; after the 10s countdown it sends 24 original Sprite frames as consecutive ActivityKit content-state updates separated by approximately 83ms. iOS may throttle, delay, merge, or drop intermediate frames. **This is not a supported 12-FPS video API**, even though each frame is genuine. The same frames can show on compact, expanded, minimal and Lock Screen Live Activity as state updates arrive. Count how many distinct intermediate shapes you actually observe.
2. **Expanded Notification — proper sprite playback in an authorized UI.** In Bloub press **MORPH notification · 24 frames / 2s**, swipe Home, wait for the local banner, then **long-press** the banner to expand it. The custom Notification Content Extension plays 24 genuine source frames with `UIImageView.animationImages`, duration 2s, 1 repetition, leaving the triangle at the end. This is an actual 2-second sprite animation, but **only after expanding the notification**. The system-drawn collapsed banner cannot play it.
3. Other v3 experiments are retained: 5-pose Island parade, delayed Attention alert, standard rich notification, Lock/Home Widgets on slow system-managed timeline, in-app diagnostic avatar. The notification extension still supports full 144-frame loops in non-morph mode.

## Explicit iOS limits

Apple's 2-second rule applies to **Live Activity UI transition animations**, not to unrestricted playback of 24 sprite images inside Dynamic Island. Live Activities are system-rendered; frame update requests are not per-frame render guarantees. Even if GitHub compiles, only a real iPhone can establish behavior. The static WidgetKit Home/Lock widgets cannot play a timed sprite sequence continuously; the Live Activity can receive updates. Always-On / reduced luminance may suppress animations.

## Install via Windows + Sideloadly

1. Stop existing Live Activity in v3. Install unsigned v4 IPA via **Sideloadly** using the same Apple Account (the existing bundle ID remains `com.bloub.island.poc`).
2. Run Island experiment then expanded notification experiment. If iOS asks for notifications, allow. Do not force-quit the app while performing the delayed Island sequence.
3. Record which surfaces genuinely animate. The **expanded notification** is the stronger native animation test, while the **Island** is intended to test whether Apple coalesces frame updates.

Project generated by XcodeGen, built on GitHub Actions macOS runner. Both widget and notification extensions have required nonempty `CFBundleDisplayName` values (checked at build time).
